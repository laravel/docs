<a id="introduction"></a>
## Introdução

Os "contratos" do Laravel são um conjunto de interfaces que definem os serviços principais fornecidos pelo framework. Por exemplo, o contrato `Illuminate\Contracts\Queue\Queue` define os métodos necessários para enfileirar jobs, enquanto o contrato `Illuminate\Contracts\Mail\Mailer` define os métodos necessários para enviar e-mails.

Cada contrato possui uma implementação correspondente fornecida pelo framework. Por exemplo, o Laravel fornece uma implementação de fila com uma variedade de drivers, e uma implementação de mailer alimentada pelo [Symfony Mailer](https://symfony.com/doc/current/mailer.html).

Todos os contratos do Laravel estão em [seu próprio repositório no GitHub](https://github.com/illuminate/contracts). Isso fornece um ponto de referência rápido para todos os contratos disponíveis, bem como um pacote único e desacoplado que pode ser utilizado ao construir pacotes que interagem com os serviços do Laravel.

<a id="contracts-vs-facades"></a>
### Contratos vs. Facades

As [facades](../facades/) e funções auxiliares do Laravel fornecem uma maneira simples de utilizar os serviços do Laravel sem precisar fazer type-hint e resolver contratos a partir do service container. Na maioria dos casos, cada facade possui um contrato equivalente.

Diferentemente das facades, que não exigem que você as injete no construtor da sua classe, os contratos permitem definir dependências explícitas para suas classes. Alguns desenvolvedores preferem definir explicitamente suas dependências dessa forma e, portanto, preferem usar contratos, enquanto outros desenvolvedores apreciam a conveniência das facades. **Em geral, a maioria das aplicações pode usar facades sem problemas durante o desenvolvimento.**

<a id="when-to-use-contracts"></a>
## Quando Usar Contratos

A decisão de usar contratos ou facades depende do gosto pessoal e do gosto da sua equipe de desenvolvimento. Tanto contratos quanto facades podem ser usados para criar aplicações Laravel robustas e bem testadas. Contratos e facades não são mutuamente exclusivos. Algumas partes da sua aplicação podem usar facades enquanto outras dependem de contratos. Desde que você mantenha as responsabilidades da sua classe focadas, notará pouquíssimas diferenças práticas entre usar contratos e facades.

Em geral, a maioria das aplicações pode usar facades sem problemas durante o desenvolvimento. Se você estiver construindo um pacote que se integra a vários frameworks PHP, pode querer usar o pacote `illuminate/contracts` para definir sua integração com os serviços do Laravel sem precisar requerer as implementações concretas do Laravel no arquivo `composer.json` do seu pacote.

<a id="how-to-use-contracts"></a>
## Como Usar Contratos

Então, como você obtém uma implementação de um contrato? Na verdade, é bastante simples.

Muitos tipos de classes no Laravel são resolvidos pelo [service container](../container/), incluindo controllers, event listeners, middleware, jobs enfileirados e até closures de rotas. Portanto, para obter uma implementação de um contrato, basta fazer "type-hint" da interface no construtor da classe que está sendo resolvida.

Por exemplo, dê uma olhada neste event listener:

```php
<?php

namespace App\Listeners;

use App\Events\OrderWasPlaced;
use App\Models\User;
use Illuminate\Contracts\Redis\Factory;

class CacheOrderInformation
{
    /**
     * Create the event listener.
     */
    public function __construct(
        protected Factory $redis,
    ) {}

    /**
     * Handle the event.
     */
    public function handle(OrderWasPlaced $event): void
    {
        // ...
    }
}
```

Quando o event listener é resolvido, o service container lerá os type-hints do construtor da classe e injetará o valor apropriado. Para saber mais sobre o registro de itens no service container, confira [a documentação dele](../container/).
